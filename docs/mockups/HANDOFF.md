# Restaurant mockups: Sage 11 handoff

**One component system, three style directions.** These are static HTML/CSS mockups for a demo multi-location restaurant group set in historic tourist districts ("old world meets modern"). Every page uses one stylesheet. A theme is a set of tokens scoped to `<html data-theme="…">`.

| `data-theme` | Brand | Direction | Display / Text font | Palette |
|---|---|---|---|---|
| `lampwright` (default) | **Lampwright**, Dining Rooms, est. 1888 | Candlelit Old Town | Bodoni Moda / Mulish | brown-black, aged brass, candle glow |
| `ember-arch` | **The Ember & Arch**, Tavern & Hearth, est. 1902 | Brick & Ember | EB Garamond / Outfit | brick, ember orange, chalkboard |
| `ashlar-iron` | **Ashlar & Iron**, Dining Room & Wine Bar, est. 1874 | Limestone & Iron | Marcellus / Alegreya Sans | limestone (light theme), wrought iron, claret |

Layout, markup and components are the same across all three. Only these change per theme:
- tokens (colour, type, radii, shadows, illustration palette, a few component knobs)
- brand copy and locations (in the mockup, a small JS map does the swap)
- two themed art swaps: lantern vs pub sign in the hero, and brick vs ashlar walls

```bash
cd mockups && python3 -m http.server 8765   # open http://localhost:8765/
```

- The location switcher sits in the utility bar and drawer. It is stored in `localStorage['rm-loc']` and sets `<html data-loc="0|1|2">`.

## 1. Tokens: Tailwind v4 `@theme`

Paste **`app-theme.css`** into `resources/css/app.css` after `@import "tailwindcss";`. Its structure:

```css
@import "tailwindcss";

@theme static {               /* `static` = always emit every var, even unused ones */
  --breakpoint-sm: 40rem; --breakpoint-md: 48rem; --breakpoint-lg: 64rem;
  --breakpoint-nav: 73.75rem; --breakpoint-xl: 80rem;
  --color-*: initial;         /* drop Tailwind's palette: brand tokens only */
  --color-bg: #15110D; --color-surface: #201A14; --color-surface-2: #2A2219;
  --color-text: #F2E6D3; --color-muted: #AD9F8A;
  --color-accent: #C79A55; --color-accent-contrast: #17120B; /* …all Lampwright defaults… */
  --font-display: "Bodoni Moda", "Didot", Georgia, serif;
  --font-sans: "Mulish", system-ui, sans-serif;
  --radius-card: 3px; --radius-btn: 2px; --radius-chip: 999px; --radius-input: 2px;
  --shadow-card: 0 18px 40px -24px rgb(0 0 0 / .55);
  --text-xs … --text-5xl: fluid clamp() scale
}

:root, [data-theme="lampwright"] { /* non-utility knobs: --space-*, --il-* illustration palette, --hero-scrim, --wm-track… */ }
[data-theme="ember-arch"]  { --color-bg: #1F1410; --color-accent: #E2692A; --font-display: "EB Garamond", …; --radius-card: 6px; … }
[data-theme="ashlar-iron"] { --color-bg: #EFE6D6; --color-text: #231C17; --color-accent: #7A2A2E; --font-display: "Marcellus", …; … }
```

Why it is built this way:
- **`@theme static` is required.** Without it, Tailwind tree-shakes variables that no utility uses, and the `[data-theme]` overrides (plus the `--il-*` illustration vars used inside SVG) would point at nothing.
- Utilities are generated **once**, from the default values. Because every utility reads `var(--color-…)`, `bg-surface`, `text-accent`, `font-display`, `rounded-card` and `shadow-card` re-skin automatically when `data-theme` changes. You never need `ember-arch:` variants. If you want one, add `@custom-variant ember (&:where([data-theme="ember-arch"] *));`.
- `--breakpoint-nav` (1180px) is where the full desktop nav appears (`nav:flex`).
- `--color-line` is `color-mix()` from `--color-text`, so it follows each theme.
- Sage 11's `@roots/vite-plugin` writes `theme.json` from `@theme`, so editor palettes and fonts come from the default (Lampwright) values. See §2.4 for editor theming.

`tokens.json` contains the same data in **DTCG** format (`$value`/`$type`): `base` plus `themes.{lampwright|ember-arch|ashlar-iron}`, ready for Style Dictionary or Figma Tokens.

## 2. Theme switcher in Sage

In production you will normally pick **one** direction per client site with a Customizer default and hide the switcher. Keep the visitor switcher for demo or pitch sites with a toggle.

### 2.1 No-flash bootstrap (inline, before any CSS)
`resources/views/partials/theme-bootstrap.blade.php`
```blade
@php($allowed = ['lampwright', 'ember-arch', 'ashlar-iron'])
<script>
(function(d){try{
  var ok=/^({{ implode('|', $allowed) }})$/, k='rm-theme',
      q=new URLSearchParams(location.search),
      t=@if($switcher) q.get('theme')||localStorage.getItem(k)|| @endif d.documentElement.dataset.theme;
  if(!ok.test(t)) t='{{ $themeDefault }}';
  @if($switcher) localStorage.setItem(k,t); @endif
  d.documentElement.dataset.theme=t;
  var l=localStorage.getItem('rm-loc'); if(/^\d+$/.test(l)) d.documentElement.dataset.loc=l;
}catch(e){}})(document);
</script>
```
`resources/views/layouts/app.blade.php`
```blade
<!doctype html>
<html @php(language_attributes()) data-theme="{{ $themeDefault }}">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    @include('partials.theme-bootstrap')   {{-- MUST come before wp_head()/@vite --}}
    @php(do_action('get_header'))
    @php(wp_head())
    @vite(['resources/css/app.css', 'resources/js/app.js'])
  </head>
```
The server already prints the Customizer default on `<html>`, so even without JS the page renders the correct theme.

### 2.2 Composer + Customizer default
`app/View/Composers/Theme.php`
```php
namespace App\View\Composers;
use Roots\Acorn\View\Composer;

class Theme extends Composer
{
    protected static $views = ['layouts.app', 'partials.*', 'sections.*'];
    public const THEMES = [
        'lampwright'  => ['label' => 'Lampwright',    'title' => 'Candlelit Old Town', 'sw' => ['#15110D', '#C79A55']],
        'ember-arch'  => ['label' => 'Ember & Arch',  'title' => 'Brick & Ember',      'sw' => ['#1F1410', '#E2692A']],
        'ashlar-iron' => ['label' => 'Ashlar & Iron', 'title' => 'Limestone & Iron',   'sw' => ['#EFE6D6', '#7A2A2E']],
    ];
    public function with(): array
    {
        $default = get_theme_mod('rm_style', 'lampwright');
        return [
            'themes'       => self::THEMES,
            'themeDefault' => array_key_exists($default, self::THEMES) ? $default : 'lampwright',
            'switcher'     => (bool) get_theme_mod('rm_style_switcher', false),
        ];
    }
}
```
`app/setup.php` (Customizer)
```php
add_action('customize_register', function (\WP_Customize_Manager $c) {
    $c->add_section('rm_style', ['title' => __('Style direction', 'sage'), 'priority' => 30]);
    $c->add_setting('rm_style', [
        'default' => 'lampwright',
        'sanitize_callback' => fn ($v) => array_key_exists($v, \App\View\Composers\Theme::THEMES) ? $v : 'lampwright',
    ]);
    $c->add_control('rm_style', ['section' => 'rm_style', 'type' => 'radio', 'label' => __('Default style', 'sage'),
        'choices' => array_map(fn ($t) => $t['label'] . ' — ' . $t['title'], \App\View\Composers\Theme::THEMES)]);
    $c->add_setting('rm_style_switcher', ['default' => false, 'sanitize_callback' => 'rest_sanitize_boolean']);
    $c->add_control('rm_style_switcher', ['section' => 'rm_style', 'type' => 'checkbox',
        'label' => __('Show visitor style switcher (demo sites)', 'sage')]);
});
```

### 2.3 Switcher partial and JS
`resources/views/components/theme-switcher.blade.php`
```blade
@props(['themes', 'current'])
<div class="themesw" role="group" aria-label="{{ __('Style direction', 'sage') }}">
  <span class="themesw-label"><x-icon name="palette" /><span>{{ __('Style', 'sage') }}</span></span>
  @foreach ($themes as $key => $t)
    <button type="button" class="tsw" data-set-theme="{{ $key }}" title="{{ $t['title'] }}"
            aria-pressed="{{ $key === $current ? 'true' : 'false' }}">
      <span class="tsw-sw" style="--sw-a:{{ $t['sw'][0] }};--sw-b:{{ $t['sw'][1] }}" aria-hidden="true"></span>
      <span class="tsw-l">{{ $t['label'] }}</span>
    </button>
  @endforeach
</div>
```
Use it in `sections/header.blade.php` (utility bar) and in `partials/drawer.blade.php`, wrapped in `@if($switcher)`.

`resources/js/modules/theme.js` (vanilla, ~0.4 KB)
```js
const root = document.documentElement;
export function initTheme() {
  const sync = t => document.querySelectorAll('[data-set-theme]')
    .forEach(b => b.setAttribute('aria-pressed', String(b.dataset.setTheme === t)));
  sync(root.dataset.theme);
  document.addEventListener('click', e => {
    const b = e.target.closest('[data-set-theme]'); if (!b) return;
    const t = b.dataset.setTheme;
    root.dataset.theme = t; try { localStorage.setItem('rm-theme', t); } catch {}
    sync(t); document.dispatchEvent(new CustomEvent('rm:theme', { detail: t }));
  });
}
```
Alpine alternative: `Alpine.store('site', { theme: root.dataset.theme, set(t){ this.theme = t; root.dataset.theme = t; localStorage.setItem('rm-theme', t) } })`, then `:aria-pressed="$store.site.theme === '{{ $key }}'"` and `@click="$store.site.set('{{ $key }}')"`.

**Copy swap.** In WordPress the brand name, crest and locations are real content, so the mockup's `content.js` map **is not needed**. If a demo site really must swap brand copy live, render all three strings and toggle them with CSS (`.show-lampwright{display:none} [data-theme=lampwright] .show-lampwright{display:revert}`), the same way the mockup swaps its themed art.

### 2.4 Editor and optional style variations
- Block editor iframe: enqueue `editor.css` (built from the same tokens). Set the theme there too: `add_action('enqueue_block_assets', fn () => is_admin() && wp_add_inline_script('wp-blocks', "document.documentElement.dataset.theme='".esc_js(get_theme_mod('rm_style','lampwright'))."'"));`
- Optional: add `styles/ember-arch.json` and `styles/ashlar-iron.json` theme.json **style variations** that remap the same palette and font slugs. These are useful if editors pick the direction in Site Editor → Styles; read the active variation in PHP instead of `theme_mod`. Use one mechanism or the other, not both.

## 6. Booking states (provider-agnostic)

`x-booking-panel` switches on `location.booking_mode`:
1. **native**: party size select, date, time slots (radio chips), name/email/phone, notes, consent, submit. Validation messages and a success state are designed. Wire it to the provider API or a form plugin.
2. **opentable / resy**: an embed container showing the provider name, a "Loading availability…" chip and skeleton slot rows (`aria-busy="true"`). This is the state before the widget mounts. In WP, load the third-party script on interaction or consent (or lazily when the panel enters the viewport), never in `<head>`. Always keep a fallback link to the provider page.
3. **call**: a "Bookings by phone" card with a large tel: button, the hours phones are answered, and a walk-ins note.

The reservations page shows all three in its "Provider-agnostic booking states" section (documentation only, so drop it in WP).

## 8. Interactions

**Recommendation: Alpine.js** (~15 KB gz). It fits Sage's Blade-first workflow, and each component below is a small `x-data`. Use the **WP Interactivity API** instead only if these UIs become blocks (it needs `wp_register_script_module` and `data-wp-*` directives; the state shape is the same). Everything degrades gracefully: without JS all menu panels render stacked, links work, and forms post.

## 9. Open-now status (production)

Compute it in PHP from the location's hours, `wp_timezone()` and the holiday overrides. Render `open` / `closing-soon` (<60 min) / `closed · opens Fri 5:30pm` server-side, so it is correct without JS. Page caching makes that stale, so also print the hours as JSON (`data-hours`) and let ~1 KB of JS recompute on load and every 60s. Status text is plain text, not `aria-live`, to avoid chatter.

## 11. Heading map and accessibility

One H1 per page, verified in the generated HTML:
```
Home          h1 Hero line ("Supper by candlelight on the old cobbles.")
              h2 Signatures of the house → h3 ×3 dishes
              h2 From the bill of fare → h3 board title
              h2 Story · h2 What's on → h3 events · h2 Kind words · h2 Inside the houses
              h2 Private dining → h3 Send an inquiry · h2 Newsletter → h3 ×3 footer locations
Menu          h1 Menus · h2 Chef's picks → h3 dishes · h2 per category → h3 per item
Reservations  h1 Reserve a table · h2 Book at {location} · h2 Hours · h2 Good to know · h2 Getting there
About         h1 Story title · h2 A short history → h3 timeline · h2 Meet {chef} · h2 House rules · h2 Find your table
Events        h1 What's on · h2 featured · h2 All upcoming → h3 events · h2 Regulars & specials
Event         h1 Event title · h2 About the evening · h2 The menu · h2 Good to know · h2 Book this event · h2 You might also like
Gallery       h1 Gallery title (add a visually hidden h2 "Photos" above the grid in WP)

404           h1 "This lane is unlit." · h2 Or visit one of our houses
Footer        h2 newsletter title → h3 location names (in every page)
```

**A11y notes**
- **Contrast.** 23 pairs × 3 themes measured, all WCAG 2.2 AA (`contrast.json`). Lowest text pairs: Lampwright muted/surface **6.65:1**, Ember accent link/surface **4.86:1**, Ashlar eyebrow/bg **5.0:1**. Lowest UI pair: Ashlar closing-soon dot/surface **3.24:1** (≥3:1, and the status is also given as text). Text on the hero is always over the scrim token.
- **Focus.** A 2px `--color-focus` outline with offset on every interactive element (`:focus-visible`). It is never removed.
- **Targets.** Buttons, chips, tabs, icon buttons, mobile-bar items and the switchers are all ≥44×44px.
- Skip link to `#main`. Landmarks: `header`, `nav[aria-label]` (primary, mobile, breadcrumb, footer), `main`, `footer`.
- **Forms.** Visible `<label>`s, required fields marked in text and with `required`, hints via `aria-describedby`, `autocomplete` attributes. The demo uses native validation plus a success message. In WP, add inline errors (`aria-invalid` + message) and a focused error summary. Gravity Forms / WS Form can output this.
- **Diet badges.** Each letter has a visually hidden full name and a `title`. A legend is always shown.
- **Prices.** Variant labels (Glass / Bottle, Starter / Main) are visible text next to each price, so screen readers read them in order.
- **Images.** Decorative SVG is `aria-hidden`. Real photos need alt text (gallery captions → alt).
- **Motion.** `prefers-reduced-motion` turns off transitions, smooth scroll and hover zoom.
- No autoplay, no sliders, no hover-only information.

## 12. Performance budget

Measured mockup weight (`weight.json`), home at 1440 with gzip, no photos:
| Theme | Requests | Transfer |
|---|---|---|
| Lampwright | 9 | ~147 KB |
| Ember & Arch | 9 | ~146 KB |
| Ashlar & Iron | 9 | ~124 KB |

Most of that is the inline SVG illustration HTML, which photos will replace.

**Budget: home < 1 MB transferred** (target ≤ 800 KB):
- CSS ≤ 25 KB gz (Tailwind output + components)
- JS ≤ 30 KB gz (Alpine + modules). Third-party booking/maps load on interaction only.
- Fonts ≤ 120 KB (2–3 woff2, Latin subset, one theme)
- Images ≤ 600 KB:
  - hero AVIF ≈ 150–200 KB at 1920 (`fetchpriority="high"`, no lazy load)
  - 3 dish cards ≈ 3 × 45 KB
  - gallery mosaic ≈ 5 × 30 KB, lazy-loaded
  - remaining thumbnails lazy-loaded
- LCP < 2.5s (hero image or H1), CLS < 0.05 (always set width/height/aspect-ratio), INP < 200ms.
- No map iframe on load (static engraved map plus a link). No embedded Instagram feed.
